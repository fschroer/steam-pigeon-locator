# ADR-0014: MapLibre for the app map — offline satellite caching, and the tile-licensing constraint

- **Status:** Accepted (map stack); tile provider for release **unresolved — see Consequences**
- **Date:** 2026-07-16
- **Deciders:** fschroer
- **Related issues:** [#26](https://github.com/fschroer/steam-pigeon-locator/issues/26) (tile-provider licensing — release blocker)
- **Clarified 2026-11-09:** the z16 ceiling recorded below is **`USGSImageryOnly`'s pre-rendered basemap cache**, not NAIP's. NAIP source imagery is 30–100 cm and clears the resolution bar — see Consequences. The decision itself is unchanged.

## Context

Recovery happens where there is no cell signal. The app map is the tool for walking to a rocket that may be kilometers downrange, so an online-only map fails at the exact moment it is needed. `DownloadMapScreen` had existed as a UI stub — buttons, no download logic — and the live map was a plain `GoogleMap` with `MapType.SATELLITE`, i.e. online tile streaming. Offline was an intended-but-unbuilt feature.

The **Google Maps SDK exposes no offline API** on Android or iOS. (The consumer Google Maps app has offline areas; the SDK does not expose them, and those areas contain vector road data, not satellite imagery — see "Alternatives".) Offline satellite was therefore unreachable without replacing the map stack.

A native iOS port is under consideration. MapLibre Native runs on Android *and* iOS from the same style JSON and the same offline-pack model, so the map layer is one of the few pieces that can be designed once for both.

## Decision

We will render the app map with **MapLibre Native** (`org.maplibre.gl:android-sdk`) instead of Google Maps, and cache satellite tiles for a launch site as MapLibre **offline regions** so the live map renders with no connectivity.

Specific enough to check code against:

1. **The map lives behind `app/.../ui/MapLibreCompat.kt`.** `MapLibreCameraState` is a Compose-observable camera mirroring maps-compose's `CameraPositionState` (read `position`, observe `moveStartedReason`, assign `position` to move the map). `MapLibreMapView` hosts the `MapView` via `AndroidView`; the rocket marker, GPS-accuracy ring and flight path are **GeoJSON style layers**, not declarative children.
2. **Bounds fitting uses MapLibre's pure `getCameraForLatLngBounds(bounds, padding, 0.0, 0.0)` query — never a `moveCamera` "probe".** A probe moves the camera mid-frame; MapLibre's GL thread renders continuously and draws that intermediate state, which appears as a persistent wobble whenever auto-zoom is on. Fit **north-up and flat** (bearing 0, tilt 0): tilt is already compensated separately by `zoomCorrection`, so letting the SDK also account for it corrects twice.
3. **Offline regions are created by `ui/OfflineMapManager.kt`.** MapLibre's offline downloader accepts **only an `http(s)` style URL** — it rejects `asset://`, `data:` and `file://`, stalling the region at "0/1 tiles". The app therefore serves the style from a short-lived `LocalStyleServer` bound to `127.0.0.1` for the duration of a download. **`res/xml/network_security_config.xml` (localhost-scoped cleartext) is required by this, not leftover scaffolding.**
   - **A region's definition is immutable and permanently records that `127.0.0.1:<port>` URL**, including the ephemeral port of the session that created it. Resuming an interrupted region therefore re-binds `LocalStyleServer` to **that exact port**, parsed back out of `definition.styleURL` — a fresh port would serve a URL the region will never request. If the port is taken the resume proceeds anyway, because the style is normally already in the offline DB from the first attempt and only tiles are refetched. Anything that changes how `LocalStyleServer` picks its port breaks resume.
4. **The live map and the downloader must resolve the same tile source** (`SatelliteProvider` + `MapProviderPrefs`). MapLibre keeps one app-wide offline database and serves any tile whose URL matches, so a provider mismatch silently yields a blank offline map.
   - The style URL is localhost for every provider, so it cannot identify the source after the fact. The provider is therefore **recorded in the region's metadata** alongside the site name, and a resume rebuilds the style from that rather than from whatever is selected now — otherwise resuming a Mapbox region under Esri stitches two sources into one region. Regions predating this metadata fall back to the current selection.
5. **MapLibre's camera zoom runs ~1 level deeper than Google's** (512- vs 256-px tile convention). Any zoom/scale math must use the MapLibre convention — the scale bar uses `78271.51696 * cos(lat) / 2^z` m/px.
6. **A download is owned by the process, not by `DownloadMapScreen`.** MapLibre's `OfflineManager` is process-wide and nothing on the screen's exit path deactivates the region, so a download survives navigating away and stops only with the process. Progress, the cancel handle and the terminal result live in `OfflineDownloadRepository` so a later visit re-attaches, instead of showing a blank slate with the Download button re-armed over a download that is still running.
7. **`OfflineRegionStatus.isComplete` cannot be trusted on its own.** It is `completedResourceCount >= requiredResourceCount`, and the required count is a *lower bound* — initially zero — until `isRequiredResourceCountPrecise` flips true. A just-created or barely-started region therefore reports `0 >= 0` and calls itself complete. Every completion verdict goes through `isDefinitelyComplete()`, which requires precision first. Without it the region list presents started-but-empty regions as fully cached — the one thing an offline-coverage list must never do — and the download observer can mark a region finished before it has fetched anything.

## Consequences

**Easier**

- Offline satellite at a launch site — verified on-device, air-gapped (airplane mode **and Wi-Fi off**, ambient cache cleared): a downloaded region renders as a hard-edged rectangle of imagery with nothing outside it. (The "clear ambient cache" control used for that check has since been removed from the screen; the hard edge is itself the tell — imagery continuing past the region boundary is ambient browse cache, not the region.)
- One map stack and one style JSON shared with a future iOS port.
- No Google Maps API key. `maps-compose` (×3), `play-services-maps` and the `com.google.android.geo.API_KEY` meta-data are removed. `play-services-location` stays — it provides the fused location provider.

**Harder / risks**

- **RELEASE BLOCKER — no wired tile provider permits what this feature does.** Verified against current terms 2026-07-16:
  - **Mapbox** — Product Terms **§2.9.1**: "Customer shall use the Mobile SDKs as Customer's exclusive means of accessing the Service Offerings in mobile applications" (rendering Mapbox tiles via MapLibre violates this by itself); **§2.8.1**: caching "limited to thirty (30) days", and only "up to the limits set in the Mobile SDKs… shall not circumvent or change those limits"; **§1.9**: no bulk/automated queries, no systematic download.
  - **Esri World Imagery** — bulk caching/redistribution restricted.
  - **MapTiler Cloud** — **§5.7** "temporary personal cache… single end-user only"; **§6.3** no "batch or excessive bulk download of map tiles"; **§6.2** no export "for usage outside the Service".

  Both currently wired providers (Esri, Mapbox) are therefore **evaluation-only**. Shipping as-is would breach their terms.
- **Identified clean path: NAIP** — `s3://naip-visualization` (requester-pays, `us-west-2`), **"Public Domain with Attribution"**, 30–100 cm, CONUS-only, so tiles may be cached and redistributed freely. Requires a GDAL tiling pipeline plus an on-device MBTiles tile server (a natural extension of `LocalStyleServer`).
  - **The z16 ceiling is `USGSImageryOnly`'s, not NAIP's** (re-checked 2026-11-09). That service is a *pre-rendered basemap cache*: its service JSON declares `maxScale: 9027.977411` — **level 16, 2.39 m/px** — which is why it 404s above z16 at all four launch sites, urban and remote alike. Adequate for terrain context, too coarse to spot a rocket. But the imagery underneath is far finer: `USGSNAIPPlus` (a **dynamic** image service, `imagery.nationalmap.gov`, no `tileInfo`) reports `pixelSizeX/Y: 0.2999999` — **30 cm**, description "6 inches to 1 meter" — and the AWS NAIP registry says 30–100 cm. 0.3 m/px works out to **≈ z18.6** at 40° N in 256-px XYZ terms, i.e. the same neighborhood as the z19–20 where measured Mapbox bytes/tile collapse into upscaled blur. The resolution rejection therefore applies to the ready-made tile service only; **NAIP source imagery clears the bar.**
  - **Public domain is the whole point.** "USGS-authored or produced data and information are considered to be in the U.S. Public Domain" — credit requested, not required — and NAIP on AWS carries the license label "Public Domain with Attribution", i.e. explicitly redistributable, which is exactly what shipping tiles on an end-user device is. None of the Mapbox/Esri/MapTiler clauses above have an analogue here: no caching window, no SDK-exclusivity, no bulk-download ban.
  - **Two provenance caveats before trusting a given tile.** USGS warns that non-USGS material in their products "are generally marked as being copyrighted", and newer **Alaska** imagery is held out of National Map services for license reasons. `USGSNAIPPlus` also blends NAIP with state/local **high-resolution orthoimagery (HRO)**, so "it came from nationalmap.gov" is not by itself proof of public domain. Check provenance for the sites actually cached; for CONUS NAIP proper it holds.
  - **Bulk-download the source; do not scrape `exportImage` to fill offline packs.** The dynamic service tempts a `{bbox-epsg-3857}` raster source as a near drop-in, but the MapLibre style spec marks the `{bbox}` token **unsupported on MapLibre Native** (both platforms), the service sets `exportTilesAllowed: false` and caps requests at 4000×4000, and bulk-fetching a federal service for on-device packs is poor citizenship even where the data is free. Pull the requester-pays COGs (or free JP2s from the TNM download client) and tile locally.
  - **NAIP is aerial orthophotography, not satellite** — leaf-on growing season, 2–3 year refresh per state, and 30 cm only where available (many states are 60 cm). Checked 2026-11-09: no user-visible string calls the imagery "satellite" today — `strings.xml`'s only hit is `locator_satellites` (the GPS fix count, unrelated), and in the app the word appears solely in comments, the `SatelliteProvider` identifier and the `satellite_style.json` asset name. The wording a USGS provider would falsify lives in **`UserManual.md` §727** ("Choose the **provider** (Esri or Mapbox)") and in the picker's provider display names. Native resolution stays a per-site judgment — that is what the download screen's detail inset is for.
  - **Program risk argues for owning the tiles rather than the service.** A 2024 FGDC/NGAC briefing says shifting NAIP to digital delivery "severely impacted" its revenue stream and puts the program at risk. Public domain means a downloaded vintage stays usable regardless of what happens to the program.
- **Satellite imagery is inherently large.** In a raster pyramid the deepest zoom is ~75% of all tiles (the series sums to 4/3 of the top level), so each level dropped saves ~75%. Tile size also varies ~5× by zoom, so size estimates are measured **per zoom** (`SatelliteProvider.avgTileBytes(z)`), not tiles × one constant.
- **Detail beyond the imagery's native resolution is free but worthless.** Measured Mapbox bytes/tile collapse past z19 (z20 9.5 KB, z21 5.5, z22 4.0 vs ~20 KB at z17–18) — the signature of upscaled blur. Native resolution varies by site, so the useful max zoom is a per-site judgment; the download screen shows a live detail inset for exactly this.

**Revisit when:** a provider grants written permission for permanent offline caching (MapTiler §6.3 and Mapbox §1.9 both say "unless otherwise agreed in writing" — worth asking for a hobby-scale use); or the NAIP pipeline lands; or MapLibre gains a non-`http` offline style path (which would retire `LocalStyleServer`).

## Alternatives considered

- **Stay on Google Maps.** Rejected: the SDK has no offline API on either platform, so the core requirement is unreachable. (Google Maps' own offline areas are small because they store **vector road data and no satellite imagery at all** — not a like-for-like comparison.)
- **Mapbox Maps SDK** (their own, satisfying §2.9.1). Still caps caching at 30 days and at the SDK's tile limits (~6,000 default vs the 23,014 tiles one test region needed), and abandons the MapLibre layer shared with the prospective iOS port. Fights the "download a site and keep it" use case.
- **MapTiler Server/Data self-hosting.** §4.1.1 permits "download and deploy pre-rendered tilesets… for self-hosting", but bundling onto end-user devices sits ambiguously between §5.2 (display to end users) and §6.4/§3.3 (redistribution needs a custom agreement), and it carries MAU caps (100 free / 500 standard). Would need written confirmation.
- **USGS `USGSImageryOnly` tiles.** Public domain, keyless, and a drop-in URL swap (same ArcGIS `/tile/{z}/{y}/{x}` scheme as the Esri source). Rejected **as the recovery map** on resolution: z16 ceiling, 2.39 m/px. Still the cheapest honest online/terrain-context layer, and the only provider wired-or-wireable today whose terms permit keeping what it serves.
- **`USGSNAIPPlus` as a live raster source.** 30 cm and public domain, but it is a dynamic image service with no tile cache, reachable only through `exportImage` — which needs the `{bbox-epsg-3857}` token the style spec marks unsupported on MapLibre Native, and which would mean scraping a federal service to build packs. The same imagery is available for bulk download; take it that way.
